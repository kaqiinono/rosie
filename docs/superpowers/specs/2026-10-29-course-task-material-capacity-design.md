# 课程、任务池、物料与时间预测：整合设计

日期：2026-10-29。时区：Asia/Shanghai。

本文整合本轮全部需求，替代此前对“逐课确认”“按周自由度作为主要指标”“所有时间一律就近分配”的设计。当前交付是设计与实施计划，尚未实施业务代码、数据库迁移或部署。

## 1. 目标与范围

保留现有课程、周期课表、任务历史和学科模块，在课程中扩展自动分配、进度、任务池和物料关联。用户每天能看到未完成任务、累计积压、完成比例、剩余分钟，以及哪些课程可能无法在截止前完成、是否需要动用周末备用时间。

本次包含三个交付阶段：

1. 课程扩展、课程进度、任务池、任务生成、执行进度。
2. 统一物料管理、百度目录关联与上传、课程及任务中的物料使用。
3. 手动可用时间、课程风险预测、周末备用、甘特图与站内提醒。

不改动 `/today`；任务完成不回写原学科的熟练度、周计划和做题统计。不重建课程管理，不要求课程必须有作业，不自动补齐整套教材缺失内容。本次不增加系统推送、短信或外部消息服务。

## 2. 已确定的方案与取舍

| 决策 | 采用方案 | 原因 |
| --- | --- | --- |
| 课程管理 | 扩展现有课程编辑器、列表和详情 | 保留现有规则与历史，避免两套课程配置 |
| 任务生成 | 服务端定时处理，页面刷新可补偿 | 网站关闭时也能生成任务 |

| 时间判断 | 全局共享容量计算，按课程作业批次展示风险 | 防止各课程重复使用同一分钟 |
| 时间偏好 | 截止约束优先，其次尽量少用周末，等价方案优先较近时段 | 单纯就近会提前消耗本可保留的周末 |
| 周末容量 | 只取手动标记的时段，作为备用 | 不假设周末全天空闲 |

| 数学进度 | 手动勾选任务内的题目，按数量计算百分比 | 不耦合原学科答题记录 |

以下明确标为“默认”的数值与处理策略是实施建议，可在配置中调整；不是新增的用户承诺。

## 3. 课程配置与学习事件

### 3.1 两种课程仍在现有课程中管理

| 配置 | 课表课程 | 自由课程 |
| --- | --- | --- |
| 星期、周循环、起止日期、指定教学周 | 沿用现有规则 | 沿用现有规则，必须选择上课星期 |
| 准确开始/结束时间 | 必填 | 不填、不伪造时间 |
| 课表日/周/月时间网格 | 展示 | 不展示、不占据时间 |
| 课程列表、课程详情、任务入口 | 展示 | 展示，标注星期和循环规则 |
| 自动生成时机 | 实际下课时间到达 | 对应日期到达，默认当地 00:00 后首轮处理 |
| 手动操作 | 补课、停课、调整本次内容 | 修改本次内容、点击完课；可补充计划外学习事件 |

“每日推进一课”表示所选上课日内每个学习事件推进一个目录项；不等于无条件七天都推进。自由课程当日自动分配不代表已经实际上完课，界面区分“已分配”“已完课”。

规则模型使用可辨别联合：课表规则必须有起止时间，自由规则没有时间；数据库约束与前端校验一致。重复的自由课程规则在同一天归并为一个默认学习事件；课表课程同日不同时间段是不同事件。

### 3.2 生成与进度推进分别控制

课程编辑器增加科目、课程类型、目录范围、当前进度、自动分配、自动推进、绑定任务池、物料、默认截止策略。

| 自动分配 | 自动推进 | 行为 |
| --- | --- | --- |
| 开 | 开 | 到达事件时生成任务并移动下一事件的进度游标 |
| 开 | 关 | 根据当前游标生成任务，后续内容由用户调整 |
| 关 | 开 | 只推进游标；本次不生成作业 |
| 关 | 关 | 用户手动操作；允许没有任何任务池绑定 |

手动“完课并生成任务”是显式操作：根据本次内容生成已绑定任务，并按课程的推进设置更新游标。若该事件已自动分配，不重复生成；只记录实际完课状态或修订本次内容。已分配任务不会因为关闭自动分配而被删除。

### 3.3 进度的含义

- 语文：教材 → 单元 → 课文/语文园地/古诗等目录项，按已有排序推进。
- 厚海：阶段 → Unit → Lesson，不能只存一个无上下文的 Lesson 数字。
- 数学：讲次 → 教学段；教学段保存真实题目 ID 集合和显示范围，例如“例题 10–20”。按题库顺序选范围，不把显示编号当数据库 ID。
- 其他科目：可用手动目录或自由描述，不强制套用语数英结构。
- 分开保存本次学习内容、下一事件游标、实际完课标记；自动推进后，当日详情仍显示本次内容。
- 后台推进依赖已持久化、带版本的目录/教学段快照，不依赖浏览器加载学科 React Hook。

数学缺少下一教学段时暂停自动推进并提醒。补齐后从当前及未来继续，不批量补发暂停期间的任务。目录结束与目录缺失分开显示。

### 3.4 修订与补偿

先使用旧配置补偿处理已经到期的事件，再应用进度/规则修改。自动与手动并发通过用户事务锁、事件唯一键和版本号保证幂等。

修改“下一次进度”只影响尚未处理的事件；修改“本次内容”明确修订该事件。未变化的任务保留；数学保留相同真实题目 ID 的完成记录；普通百分比任务若实际学习内容变化，则保留旧修订记录、新内容从 0% 开始。仅改标题不清空进度。已完成历史不被自动改写。

停课、归档、恢复、补课、同日多次上课、规则生效日期继续使用现有语义。首次启用自动分配从启用时间生效，不把所有历史课次变成待办；已有明确生成游标的处理中断则按游标补偿，不能受课表五周预览范围限制。

## 4. 任务池与学科内容

“任务模板”入口改为“任务池”。内部保留 `task_templates` 和已有 `template_id` 以减少迁移风险，新领域名使用 `TaskPoolItem`，课程通过独立绑定关系选择池条目。

每条池任务定义：名称、科目、活动类型、触发阶段、当前/下一内容目标、适用范围、预计分钟、进度模式、物料选择器、截止和提醒规则。课程绑定可覆盖时长、范围、物料及启用状态。个人 weekly/once 任务继续保留，不要求绑定课程。

新建手动任务也必须选择科目，允许明确选择“其他/未分类”；历史空科目兼容显示为未分类，不删除旧任务。

匹配规则使用 `book/stage + unit + lesson`，并支持全部、指定目录项、指定教学段。选择了多少匹配活动就生成多少，不按可用时间删减。通用规则和专项规则默认叠加；相同 `activity_key` 的专项覆盖通用，避免同一活动重复生成。

### 4.1 厚海课程的 Lesson 定制

| 范围 | 建议池活动，可逐项启停 |
| --- | --- |
| 通用课前 | 当课 5A 单词认读、课文预习 |
| 通用课后 | 单词背诵/拼写、课文语法掌握；保留现有 workbook 活动 |
| Lesson 1 | 阅读：听读、跟读、理解课文 |
| Lesson 2 | 听记：听写单词、默写课文文章，按绑定物料执行 |
| Lesson 3 | 背诵课文；作文为独立任务，有自己的时长与进度 |

沿用现有 `lesson_filter` 的 L1 阅读/L2 听记/L3 背诵数据，迁移为完整范围条件；不丢失既有配置。允许某次课覆盖材料、任务条目或绑定其他 Lesson 的内容。

### 4.2 语文

池中提供可配置活动：会认字认读、会写字认读/书写、组词、默写、课文预习复习、日积月累、古诗词背诵及其中会写字书写、成语积累、好词好句积累。先接入现有数据与页面；缺少结构化内容时允许补充文本、图片或文件，并标明待补物料。

### 4.3 数学

题目选择保留题库分组，课堂复习默认从 `lesson` 选择，作业默认从 `homework`（课后巩固）选择；其他分组需要显式切换。可按讲次、题型、标签筛选并逐题选择。

尚未选作业时保留一个“待选题”任务和预计时长，不能把它当成零工作量或已完成；支持“本次无作业”，以明确取消原因关闭该任务。每题一项完成记录，复用原题目详情与已验证的回放视频入口；没有已确认的视频匹配时不显示可播放承诺。

## 5. 执行进度与剩余时间

- 手动百分比任务：保存 0–100 的完成百分比和修订号。
- 数学题目任务：`完成比例 = 已完成有效题数 / 当前有效题数`；空题集为待选题，比例为 0。
- `remaining_minutes = ceil(estimated_minutes × (1 - completion_ratio))`；中间比例不提前四舍五入。
- 预计时长必须为正整数分钟，可手动修正；未配置时建议默认 20 分钟，并标记“暂估”。
- 勾选题目、修改比例、修改预计分钟记录变化历史。并发更新使用原子逐项 RPC 或版本冲突，不能整份 checklist 最后写入覆盖另一设备的更新。
- 完成/取消任务不再计入未来需求，恢复任务后重新计算。课程卡片进度按预计分钟加权，不平均不同长度任务的百分比。
- 时间段被占用或已经过去，不代表任务完成。没有更新进度时剩余工作量仍存在，过期安排释放并重新预测。
- 已固定的未来任务块只为其任务抵扣一次待分配需求，同时占用一次总容量；不能既扣容量又把完整工作量重新安排一次。

## 6. 物料管理

### 6.1 物料、课程关联、任务使用是三个层次

新增 `/materials`，集中查看所有科目的文件、图片、音频、视频、文本和链接。每次上传必须指定科目。科目用于分类和默认筛选，不是禁止跨科目关联的权限边界。

一个课程可关联多个物料，一个物料可关联多个课程；关联可细化到 Unit/Lesson、课文、讲次、数学教学段或题目，并注明预习/复习/听记等用途。课程详情展示课程通用物料和按内容分组的物料列表，任务直接引用相应资产。

共享资产不等于共享个人课程：所有已登录用户可以查看/上传共用物料，课程关联仍属于各自用户。物料基础信息由上传者或管理员维护，替换文件创建新资产/版本，不原地改写既有任务引用。归档后不再出现在新选择中，已有引用仍能访问。

旧的私人任务录音保留原权限，不因新增共享物料库而变为公开物料。解除课程关联不删除百度文件；本期不提供物理删除网盘文件的联动操作。

### 6.2 相对目录路径关联

流程：选择已允许的网盘根目录 → 输入相对路径 → 选择科目及目标课程 → 获取文件清单 → 建议匹配课程目录 → 批量确认关联。

允许选择是否扫描子目录；采用分页、有界扫描和持久化断点。结果有完整/未完整状态，扫描失败不清空旧关联。规范化路径并拒绝越界路径，避免把任意输入当作可访问根目录。

候选匹配解析 Unit/Lesson、课文名、数学讲次/题号；模糊或歧义匹配必须列出候选，不能自动绑定错误课程。去重标识为百度账户稳定身份与 `fs_id`，路径是元数据而非唯一身份。课程详情支持从关联物料定位原目录、筛选、查看和解除关联。

### 6.3 百度上传与访问

已核实百度网盘存在预上传、分片上传、合并创建的接口链路。现有项目已具备服务器端主账户 OAuth、令牌刷新、音视频代理与数学回放目录；当前没有通用上传接口。

实施前需验证当前应用实际上传权限和允许写入根目录，不能因存在读取权限就认定 `/airosie` 可写。新增 `BAIDU_MATERIAL_UPLOAD_ROOT`，由服务端派生最终路径，默认唯一文件名、不覆盖已有文件。

所有登录用户共享主账户并可上传；OAuth 授权管理仍由管理员操作。浏览器不接收百度 token、service-role key 或永久带鉴权链接。

上传契约：初始化会话 → 浏览器 Worker 计算完整有序分片 MD5 → 每片 4 MiB 原始请求体上传到平台 → 平台向百度提交 → 完成时验证 `fs_id` 与文件大小 → 资产标记 ready。默认最多 2 片并发、可重试及断点续传；建议首版最大 2 GiB，可配置。浏览器关闭后需重新选择同一文件验证再续传，不承诺关闭浏览器仍上传。

分片大小的选择考虑 Vercel 请求体限制；实施时复核项目实际运行限制。完成请求结果不明时先按会话稳定路径核验，再重试合并，防止重复资产。

支持类型按能力预览：图片、常见音视频、PDF；其他文件展示元信息和下载入口。上传支持任意文件不等于浏览器可预览任意编码。授权账户改变时旧资产标为账户不匹配、上传会话失效，不静默把同路径新账户文件当成旧文件。

| 科目 | 已有来源 | 主要缺口/接入方式 |

## 7. 可用时间与周末备用

沿用现有“星期多时段 + 指定日期覆盖”的配置。周中和周末都要手动标记具体时间；周末不自动生成全天容量。周六/周日已标记时段默认属于备用，工作日属于常规；本期不自动把节假日换算成可用时间。

区分 `未配置`、`明确不可用`、`已配置时段`，可按周重复，也可为某日设置例外。未配置不增加容量，但界面显示“待配置”，不能伪装为完整且可靠的容量评估。

容量为已标记时段的并集，扣除已经过去的部分、未取消的课表课程、考试、明确不可用区间。自由课程不扣固定时长。重叠时段只算一次；指定日期覆盖整天的周期设置，不追加重复容量。分钟边界保守处理：可用区间起点向上、终点向下取整，不虚增不足一分钟的时间。

预测排期与用户固定安排分开。未来固定安排先占用相应合法时段；失效、超出可用时间、与课程冲突的固定安排明确报错并给出调整建议，不静默移动。

## 8. 按课程判断完成风险

### 8.1 展示单位与指标

主要层级为课程 → 学习事件 → 作业批次 → 任务。批次按相同触发阶段、可开始时间和截止时间分组；不同截止时间不混成一个平均百分比。周视图用于配置与观察负荷，不作为风险判断的唯一边界。

每批次显示：完成比例、剩余分钟、可开始时间、截止时间、预计完成时间、周中分配分钟、周末分配分钟、未能排入分钟、数据可信状态。课程摘要突出最近截止和最紧急批次。

不把“任务进度百分比”“截止前安排覆盖率”“可调整余量”混为一个自由度数字。覆盖率为截止前已分配的剩余分钟 / 剩余需求，任务已完成时显示已完成，不做零分母运算。

可调整余量定义为：在其他已建模需求仍可按时完成的前提下，为这个批次增加多少同执行窗口的工作分钟仍可排下。使用反事实可行性计算；各课程余量不能相加。全局已经不可行、数据缺失或固定安排冲突时，余量返回未知，优先显示缺口与冲突。

### 8.2 截止与积压

课表作业默认截止到下一次实际开课前，可单独覆盖。下一次课跨周也按真实时间计算，不截断到周日。自由课程同样需要截止时刻；建议默认下次上课日前一天 20:30，允许修改。没有下次课程且没有固定截止时，列为“待设截止”，不显示安全结论。

逾期任务继续保留原截止和逾期标记。补做安排单独使用 `recovery_due_at`；建议默认当天 23:59，用户可调整，次日滚动产生新的预测补做目标但不改写原始截止。累计未完成量一直展示，不能因为逾期而从工作量消失。

无截止且未安排的自由待办单独展示“待纳入排期”，由用户设置目标日期或安排后纳入硬约束；不能把它们默认当成本周必须完成，也不能隐藏积压。

### 8.3 未上课的任务也要预测

用相同课程事件、进度快照和任务池匹配规则推演未来任务；预测任务保留预计分钟、可开始时间、截止时间和不确定性，但不提前生成正式待办、不推进实际进度。

例如周五下课后才可做的听记，不能塞进周四；但现在就要考虑它会占用周五后的容量。正式生成后按稳定逻辑来源键替换预测，绝不能重复计数。

待选题、暂缺物料仍预留估计分钟，显示暂估/待配置。未知规则或教学段不视为零任务。预测范围默认覆盖未来 28 天，并扩展到已知任务截止与各课程下一作业截止；超过 180 天标为超出预测范围。范围内的所有课程都参与竞争，界面显示覆盖截止日；跨出范围的任务不强塞入本窗口，不对未建模的远期负荷作“保证完成”承诺。

### 8.4 分配算法

先保留合法固定安排，再把剩余可用区间按课程/考试/任务可开始时间/截止时间切段。首版任务可按整数分钟分段执行，不引入未经用户要求的强制连续时长。

建立“任务需求 → 合法可用区间”的容量网络，每分钟容量只用一次。采用最大流/最小费用流的分层目标，禁止用“逐个课程先占最近时间”的贪心代替全局计算：

1. 最大化截止前可分配的总分钟；不可能全部完成时，保护更近截止和用户显式优先级，稳定标出冲突课程组。
2. 在同样满足程度下，最小化周末备用占用。
3. 保持已采纳的固定安排；未采纳预测优先减少无意义变化。
4. 等价方案中优先使用较近的合法时段。

分别计算常规时段方案和包含备用时段的方案。最终推荐使用后者中的最少备用解；不能先用简单周中贪心锁死分配，再只拿周末补洞，否则可能产生不必要的周末占用。

所有任务预算按真实 release/deadline 约束分配；周六更近但下周一仍来得及的任务，可以优先安排到下周一。同级备用时间内部仍优先最近的可用时段。

数据变更后重新计算可移动部分，预测块不直接写入固定安排。用户“采纳”时再验证输入版本及可用性，原子保存固定块。完成百分比只由实际执行更新。

### 8.5 风险与提醒

| 状态 | 含义与提醒 |
| --- | --- |
| 周中可完成 | 常规容量可满足本次预测中的需求 |
| 周中紧张 | 仍可完成，但可调整余量少；显示实际剩余分钟，不只显示颜色 |
| 需要周末 | 使用备用后可完成；列出课程、日期/起止时间、预计备用分钟与合计 |
| 需要调整安排 | 固定安排冲突或当前计划超时，但解除可移动冲突后存在可行方案 |
| 时间不足 | 纳入已标记周末后仍存在缺口，显示冲突组、课程、截止日期和缺少分钟 |
| 待配置/暂估 | 时段、截止、任务时长或物料不完整；不能显示确定安全 |

默认“紧张”阈值建议为批次剩余需求的 20% 可调整余量，允许配置；不是每周统一自由度阈值。零余量标为刚好排满。若删去今天的容量将导致超期，通过反事实计算显示“今天至少完成 X 分钟”，不能用当前排期中的今天分钟数冒充必需量。

同时计算全局今日最低投入与单批次今日最低投入。可相互替换的课程可能各自最低为零，但全局今天仍必须做一定分钟；此时显示全局必需量和建议课程，不把每门课建议量都称为不可替代的最低量。

站内提醒在首次出现、级别变坏、缺口增加、周末占用增加或临近必须执行时更新。相同用户/批次/风险原因只保留一个活动提醒；已读不代表已解决，风险解除后标记解决。普通重算不每分钟新增提醒。

若多个课程共同争用不足容量，缺口归属会随优先级变化；界面显示“当前方案缺口”和相关冲突课程，不宣称其中某门课在任何方案下都必然失败。

## 9. 甘特图

以课程/批次为行，可展开任务；时间轴支持自然日期概览和可用时段展开。默认滚动查看与当前课程截止相关的周期，不固定锁定本周。

- 展示最早可开始点、预计执行片段、截止标记与已固定安排。
- 周末列/时段有备用底色；未手动标记区域为不可用，不计容量。
- 正式任务与未来预测有文字和线型区分；已完成进度与预计排期用不同标记。
- 行末直接显示剩余分钟、需周末分钟和缺口，不只依靠长条或颜色。
- 切换“仅周中 / 允许已标记周末”比较；选择课程能查看其分配、冲突和原始任务。
- 缩小后聚合为每日片段，不能让短任务完全不可见；展开或聚焦可查看精确起止时间。
- 可用时间折叠视图必须明确注明非自然时间比例，日期/钟点可查；不把周五下课后的预测显示成周四可执行。
- 若提供拖动，视为排期编辑并需保存/采纳，不能直接修改任务完成度。首版可用点击编辑代替拖动。
- 支持键盘、手机、非颜色辨识；始终提供同数据的可读列表。

示意甘特图仅用于确认表达方式，不是当前用户真实课程数据，也不是完整求解器实现。

## 11. 后台、版本与上线

课程生成用每分钟 Supabase Cron 调用受限的私有 worker，数据库锁、稳定事件键和游标保证重试安全。现有 `task_user_lock` 面向用户鉴权，不能直接假定 postgres Cron 会具备 auth.uid；抽离内部受限逻辑和用户入口包装。

任务/课程/时段变更原子增加用户规划输入版本并置 dirty。后台规划使用同一 TypeScript 求解器：Cron 经 pg_net 调用受密钥保护的内部 Next.js 路由，从数据库领取有租约的 dirty 用户任务；不信任请求体传入的任意用户 ID。密钥放服务端环境与数据库 Vault，不下发浏览器。分页领取、有限并发、超时释放、失败退避，旧输入版本计算结果不得覆盖新结果。

网页可快速本地预览并请求本人重算，但网站关闭不应阻止生成和风险更新。后台中断时显示最后计算时间及过期状态，恢复后补偿；不能展示旧的绿色结论而不提示。

迁移以增量为主，旧 ID、任务完成记录、私人录音和课表历史保留。旧课程迁移为课表课程；缺少推进配置的课程显示待配置，不凭猜测启用自动推进。旧确认入口下线但确认历史可读。旧 `/tasks/templates` 保持重定向或兼容入口到任务池，`/tasks/materials` 引导至统一物料和个人关联。

先部署兼容读写及新数据结构，再启用后台和新界面，最后停用旧确认生成路径；全程避免新旧生成器并行重复发任务。可单独关闭自动生成/预测 worker 保留已生成数据，不能用删表方式回退。

## 12. 验收重点

1. 不打开网站，课表下课与自由课程日期到达均能生成；同一事件多次触发只有一批任务。
2. 自由课程没有钟点，保留星期/周循环，不出现在课表时间网格。
3. 四种自动开关组合、手动完课、进度修订、停课、补课都符合第 3 节。
4. 厚海 L1/L2/L3 匹配正确，L3 背诵和作文独立；通用覆盖不重复。
5. 数学真实题目范围、课后巩固选题、待选题、逐题百分比与已有回放可用。
6. 任意科目课程能关联多个任意类型物料；目录建议、确认、课程详情和任务引用贯通。
7. 所有登录用户可共享查看/上传；用户 A 不能改用户 B 的个人课程关联；百度凭据不暴露。
8. 60 分钟任务完成 25% 后剩余 45 分钟；3 题完成 1 题、预计 20 分钟时剩余 14 分钟。
9. 跨周截止、尚未开课任务、固定安排和剩余容量一起计算，不重复占用。
10. 周末只计算手动标记时段；未配置不当作全天可用；正常/备用/仍不足分别展示。
11. 示例总需求 270 分钟、周中 180、有效周末 120 时，满足时间窗口后备用需求为 90；周中有效增加 60 后为 30；周末设为零后缺口 90。
12. “周中增加时间”只有在相关任务的可开始与截止之间才有效；不能单靠总分钟差声称可完成。
13. 甘特图的区间、合计和风险使用同一规划结果；任务进度、时间经过和排期采纳互不混淆。

## Final integration scope (2026-10-30)

Planning freezes a nominal release cohort of at least28 days, extended for known actual deadlines
and each course’s next homework deadline, capped at180 days. It then closes that cohort’s known
crossing deadlines (also capped at180) and admits all otherwise eligible forecast work due by the
final analysis end, including competing extension-period work. Admission does not recursively
extend for later recurring releases. `release_cohort_end` and `horizon_end` record the two bounds.
Later nonadmitted work produces visible advisory `forecast_boundary` notices; missing inputs and
admitted deadlines beyond the cap remain incomplete. Headroom and risk describe only this finite
modeled scope, never all future work.

Actual selected material IDs stay frozen. The application adapter checks their current catalog
availability; pending/missing/account-mismatched assets retain estimated work but make its certainty
incomplete. The service snapshot also reports `current_available` using the verified current
Baidu account, allowing archived-but-readable references while rejecting archived assets of an old
account. Credential changes increment the shared planning epoch; no selection/history rewrite occurs.
