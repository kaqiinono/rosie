# 第一步：数据文件

`packages/math-content/src/utils/g{grade}/lesson{seq}-data.ts(x)`，如 `2-11` → `g2/lesson11-data.ts`。

骨架复制同年级上一讲，先清除旧题内容、旧真实 ID 和旧 `displayId`，再根据教材映射填新题。

## 题目 ID

本节集中维护完整编号规范；skill 与模板保留关键约束并链接此处。

### 新课程：先映射再生成

格式为 `{lessonKey}-{完整后缀}`，可用 `problemIdForLesson('2-11', 'L1-1a')`。先整理“教材题号 → 例题/练一练归属 → 平台 ID”：

| 教材题号 | 归属 | 后缀 | 新真实 ID（以2-11为例） |
| --- | --- | --- | --- |
| 例题1 | 例题1 | `L1` | `2-11-L1` |
| 例题1下第一个练一练 | 例题1 / 练一练1 | `L1-1` | `2-11-L1-1` |
| 例题1下第二个练一练 | 例题1 / 练一练2 | `L1-2` | `2-11-L1-2` |
| 例题2(1) | 例题2 / 小题1 | `L2a` | `2-11-L2a` |
| 例题2(2) | 例题2 / 小题2 | `L2b` | `2-11-L2b` |
| 例题2下练一练1(1) | 例题2 / 练一练1 / 小题1 | `L2-1a` | `2-11-L2-1a` |
| 例题2下练一练1(2) | 例题2 / 练一练1 / 小题2 | `L2-1b` | `2-11-L2-1b` |
| 例题4（教材跳过3） | 例题4 | `L4` | `2-11-L4` |

- 例题保留教材原号和跳号。练一练在所属例题下独立编号，不占用下个例题号；有原编号时沿用，无原编号且归属明确时从1编号。
- 拆分成独立题的小题使用小写字母：原1/2 → a/b，原1/2/4 → a/b/d；原字母直接保留。不要补题、压缩跳号；超过字母范围、重复来源号或层级不明先询问。
- 保留 `title` 中的教材编号和题意。未拆分的整题保留整题号，不因题干多问擅自拆历史题。
- 新课禁止 legacy 前缀（`56-L1`）、裸 `L1` 及 `displayId`，真实 ID 本身正确。同讲次真实 ID、有效显示编号分别唯一。
- 课前测 `P`、作业 `H`、练习册 `W`、附加题 `S` 沿用各来源的教材规则；本次不重编已有其他来源，包括旧 LESSON 中的附加题。
- 总结 sentinel：`2-11__SUMMARY`。
- 结合例题分组、标题、题型和教材顺序推断练一练归属；不能只因缺少“属于例题N”的文字就列为待确认。数组索引或骨架旧 ID 不作为业务题号。推断后仍有冲突才询问；会话已确认规则不重复询问。

### 旧课程：仅显示兼容

真实 ID 被学习记录、掌握度、收藏、错题、草稿、笔记、图片、计划和试卷引用，**禁止重命名旧真实 ID**。数组顺序、导航索引和数据库关联保持不变。

仅需纠正且有依据的旧课堂题显式填 `Problem.displayId?: string`（短题号）；已正确的不重复填。已确认的第2-10讲示例：旧 `2-10-L2` 显示 `L1-1`，旧 `2-10-L3` 显示 `L2`。

统一使用 `@rosie/math-kit/utils/problem-display-id` 的 `problemDisplayId(problem)`：优先 displayId，否则去掉 canonical/legacy 讲次前缀，保留完整后缀。`2-11-L1-1a`、`56-L1-1a` 均显示 `L1-1a`，禁止取最后一个 `-` 片段。来源分类仍按真实 ID 的完整后缀。

业务题号展示接入此函数；练习进度、试卷顺序号及技术审计真实 ID 保持原义。所有存储、路由、收藏与草稿操作继续传真实 `problem.id`。

新旧题均可结合分组、标题、题型及教材顺序推断，不要求练一练标题与例题主题逐字相同：

- 常规“例题N → 练一练 → 下一例题”结构，练一练归属例题N；同一例题的多个小题仍是同一分组，其后的练一练不归到单独的字母小题。
- 同组独立练一练依次为 `LN-1`、`LN-2`；本组已有独立练一练编号和跳号时保留，例如例题2下“练一练1、4”为 `L2-1`、`L2-4`。
- 同一个练一练的 `(1)/(2)` 小题为 `LN-1a`、`LN-1b`；例如“练一练 · 凑整(1)/(2)”是一个练一练的拆分题，不额外占用 `LN-2`。
- 先列全部例题、再列对应练习时，结合两组的编号和题型对应归属；例如全讲“例1…例6，练1…练6”，每个对应练习均是所属例题下的第一个练一练。不要把全讲对应编号误作某个例题内的局部序号。
- 仅在分组或语义有冲突、跨组归属不明、重复例题号的小题号不完整，或旧题同时保留整题及重叠拆分题时，保留旧号并记录待确认；不能为了消除重复而擅自合并、删除或重命名旧真实题。

无法确认时保留旧号，在 [题号待确认清单](../../scripts/math-problem-numbering-review.json) 的 `pending` 记录讲次、真实 ID、标题、疑点；`reviewedLessons` 记录本次旧课边界，不能为新课扩充兼容豁免。已知目标显示号被未决旧题占用时，暂缓该字段并登记，避免引入重复显示号。确认后按讲次小批次修改，移除对应待确认项。

### 只读审计（仅用户手动运行）

```bash
node scripts/audit-math-problem-numbers.mjs
node scripts/audit-math-problem-numbers.mjs --lesson 2-10 --json
node scripts/audit-math-problem-numbers.mjs --strict
```

CLI 不加载环境变量、不连网络、不读写数据库、不改文件。使用现有 TypeScript 依赖，在隔离上下文读取数据声明，支持 factory/map/spread；图形与检查器使用已知的元数据无关占位，未知依赖或读取失败报错，不静默跳过。

报告各讲覆盖、重复真实/显示 ID、不合法完整后缀、误用或冗余 displayId、待确认项及过时清单。默认 pending 不导致失败，其他问题退出1；`--strict` 将 pending 也视为失败。脚本未运行不代表检查通过；教材语义及历史引用仍需人工验收。

### 手动验收样例与历史保护

1. 用上表“例题1 → 两个练一练 → 例题2拆分小题 → 练一练拆分小题 → 跳号例题4”审阅**同一个** add-lesson skill，预期 ID 为表中值，全部无 displayId；不为样例注册真实课程。
2. 第2-10讲核对 `2-10-L2` → `L1-1`、`2-10-L3` → `L2`，并打开旧学习记录、掌握度、收藏、错题、草稿、笔记、图片、计划及试卷，确认仍归原真实题。
3. 覆盖多个练一练、`L1a`/`L1-1a`、跳号、legacy 前缀及未决旧题；筛选、排序、翻页和展开后题号稳定，窄屏长徽章不截断。
4. 对照本次改动前的工作区（含原未提交内容），核对真实 ID、顺序、导航索引、数据库引用未变。本次无迁移、无写库。
5. 所有 build/test/lint/typecheck、环境验证、依赖安装、服务启动、审计和浏览器验证由用户手动执行，代理不自动运行。
